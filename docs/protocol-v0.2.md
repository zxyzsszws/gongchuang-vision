# 串口协议 v0.2 —— 视觉 ↔ 主控（电控组冻结文档）

状态：视觉侧已按此实现并通过全量测试（`src/core/crc.py` / `src/core/protocol.py` /
`src/devices/link.py` / `src/core/fsm.py`），待与电控组联调前冻结。
**取代 v0.1**（`docs/protocol-v0.1.md` 的 `AA 55 | len | seq | cmd | payload | xor | 0D`
帧格式已废弃，仅留档）。

v0.2 只采用参考帧结构（RoboMaster 风格：5 字节 frame_header + 2 字节 cmd_id +
data + 2 字节 CRC16 frame_tail）。参考材料里的具体命令与字段内容**不作为本协议
内容**，命令码按本文件 §3 重新分配。

**本文所有字节示例均由实现代码 `encode()` 实际运行输出（非手算）。**

## 1. 物理层

- UART **115200 - 8 - N - 1**（8 数据位、1 停止位、无校验、无硬件流控）
- 参考材料给出的两档速率：电源管理模块 ↔ 机器人 **115200**，图传发送端 ↔ 机器人
  **921600**。视觉侧默认用 115200（`config/default.yaml` 的 `serial.baudrate`）；
  若现场与主控约定走高波特率，改该配置即可，协议本身与波特率无关。
- 多字节字段一律 **little-endian**。

## 2. 帧格式（冻结）

```
frame_header(5B) | cmd_id(2B) | data(n B) | frame_tail(2B)
```

| 字段 | 长度 | 说明 |
|---|---|---|
| `SOF` | 1B | 固定 **0xA5** |
| `data_length` | 2B | = `len(data) + 2`。**不含帧头与帧尾**；数字上既等于「cmd_id(2) + data」，也等于「data + frame_tail(2)」——两种理解给出同一字节布局，故无歧义 |
| `seq` | 1B | 发送方自增序号，见 §2.1 |
| `CRC8` | 1B | 覆盖 `SOF + data_length + seq` 共 **4 字节** |
| `cmd_id` | 2B | 命令码，见 §3 |
| `data` | n B | 命令数据段，可为空 |
| `CRC16` | 2B | 覆盖「`frame_header` + `cmd_id` + `data`」**整包**（不含自身）|

固定开销 = 5 + 2 + 2 = **9 字节**；单帧 data 上限 **1024 字节**（`MAX_DATA_LEN`，
远大于本协议最大帧 TASK_PLAN 的 12 字节，仅为抗乱流时快速放弃同步）。

### 2.1 seq 约定

- 视觉侧外发帧（TASK_PLAN / GOTO / CALIBRATE / PLACE / PICK / HEARTBEAT）seq 在
  **1..255** 循环自增。
- **0 保留**给链路周期性上行帧：`POSE` 与 `DONE` 的 seq 恒为 0（视觉侧对 seq=0 的
  POSE 不按 seq 去重，逐帧消费）。
- `ACK` 的有效信息在 data（被确认帧的 seq），其自身 seq 无消费语义。

### 2.2 校验参数（冻结）

| 项 | 参数 |
|---|---|
| CRC8 | 多项式 **0x31**（反射形式 **0x8C**，LSB-first）、初值 **0xFF**、无结果异或 |
| CRC16 | 多项式 **0x1021**（反射形式 **0x8408**，LSB-first）、初值 **0xFFFF**、无结果异或 |

参考材料给出的 256 项 CRC8 表首行为 `00 5e bc e2 61 3f dd 83 c2 9c 7e 20 a3 fd 1f 41`、
末值 `0x35`；视觉侧实现用算法生成该表，并以 `tests/test_crc.py` 固化对齐（17 个值
逐项断言）。CRC16 采用标准 CRC-16/X-25 去掉最终异或（`"123456789"` 的校验值
`0x6F91` 已在单测中固化）。

### 2.3 流式解析与容错

接收端实现为 `StreamDecoder.feed()`，抗粘包/断包：

1. 找 `0xA5` 作为 SOF；找不到则整段丢弃（计入 `dropped_bytes`）。
2. 帧头不足 5 字节 → 等下一批数据（**不清空缓冲**）。
3. `data_length ∉ [2, 1026]` → 判坏帧，**丢 1 字节**后重新找 SOF。
4. CRC8 不符 → 判坏帧，丢 1 字节后重新找 SOF。
5. 整帧字节数不足 → 等下一批数据。
6. CRC16 不符 → 判坏帧，丢 1 字节后重新找 SOF。
7. 全部通过 → 交出一帧 `Frame(seq, cmd, data)`。

**坏帧只丢 1 字节、绝不清空整个缓冲**：这样粘包场景下一帧损坏不会连带丢掉它
后面的好帧（`tests/test_protocol.py::test_bad_frame_does_not_eat_next_good_frame`）。
data 内部出现 `0xA5` 不会破坏同步（被 CRC8/CRC16 双重校验排除）。

## 3. 命令表

| 命令 | cmd_id | 方向 | data 结构 | 说明 |
|---|---|---|---|---|
| HEARTBEAT | `0x0001` | 双向（视觉周期发） | 空 | 500ms 周期；任一侧 2s 无来流 → SAFESTOP |
| TASK_PLAN | `0x0002` | 视→控 | 12×1B：`b1色[3] b1位[3] b2色[3] b2位[3]` | 扫码结果，开赛只发一次。颜色 1-6，位置 1-3=环编号。**按批次分组排列**（见 §6.4） |
| GOTO | `0x0003` | 视→控 | `x,y:int16(mm) heading:int16(0.1°)` | 请求导航（绝对坐标）。x/y = **FieldMap 数字环心**：NAV1/NAV2 目标取 TASK_PLAN 对应批次放置位置首位编号匹配的环心，无匹配环回退原点；RETURN 回起点 `(0,0)`。heading 当前恒发 0 |
| CALIBRATE | `0x0004` | 视→控 | `dx,dy:int16(mm) dhead:int16(0.1°)` | **修正量**（非绝对坐标），主控叠加到其推算位姿 |
| PLACE | `0x0005` | 视→控 | `id:1B fine_x,fine_y:int16(mm)` | 放置请求 + 视觉微调量。当前 FSM 第一字节填**物料颜色号**（见 §6.5） |
| PICK | `0x0006` | 视→控 | `color:1B off_x,off_y:int16(mm)` | 取料请求 + 相对偏移。协议已定义，**当前 FSM 未外发**（预留，见 §6.6） |
| ACK | `0x0007` | 双向 | `被确认帧 seq:1B` | 100ms 未 ACK 重发，3 次失败 → SAFESTOP |
| POSE | `0x0011` | 控→视 | `x,y:int16(mm) heading:int16(0.1°) odom:uint16(m)` | 10Hz 主动上报，校准输入；seq=0 |
| STATE | `0x0012` | 控→视 | `state:1B` | 主控状态；视觉侧当前仅收帧记录，FSM 推进只依赖 DONE |
| DONE | `0x0013` | 控→视 | `task_id:1B` | 单动作完成事件，FSM 状态推进依据；seq=0 |

命令码分段约定：`0x0001-0x000F` 视觉 → 主控，`0x0011-0x001F` 主控 → 视觉，
`0x0020` 以上留作扩展；因此 **cmd_id 高位字节当前恒为 0**（低字节承载命令）。

设计要点：校准走增量、主控保留推算主权；场地原点=扫码区角点，双方共用 FieldMap
（单位 mm，0.1°）。

## 4. 字节级示例（`encode()` 实际输出）

以下 hex 全部由视觉侧实现真实运行生成，电控组可直接用作收发单测的黄金样例。
复现命令（仓库根目录）：

```bash
python -c "from src.core.protocol import Frame, encode, CMD_TASK_PLAN; print(encode(Frame(1, CMD_TASK_PLAN, bytes((4,5,2,3,2,1,2,5,4,3,1,2)))).hex(' '))"
```

### TASK_PLAN（seq=1，对应二维码 `452+321+254+312`）

第一批颜色 4,5,2｜第一批位置 3,2,1｜第二批颜色 2,5,4｜第二批位置 3,1,2
（data 12 字节 → `data_length = 0x000E`，总长 21 字节）：

```
a5 0e 00 01 69 | 02 00 | 04 05 02 03 02 01 02 05 04 03 01 02 | 22 94
```

### GOTO（seq=2，x=1200mm，y=300mm，heading=45.0°→450）

```
a5 08 00 02 5a | 03 00 | b0 04 2c 01 c2 01 | f0 30
```

（`b0 04`=1200 LE，`2c 01`=300 LE，`c2 01`=450 LE）

### GOTO 实例（seq=8：NAV 目标 = FieldMap 3 号环心 (1200,900)，heading 恒发 0）

视觉侧当前真实外发的导航帧形态——目标点由 TASK_PLAN 批次位置首位匹配环心得出：

```
a5 08 00 08 24 | 03 00 | b0 04 84 03 00 00 | 42 2e
```

### CALIBRATE（seq=3，dx=−12mm，dy=45mm，dhead=8.3°→83）

```
a5 08 00 03 04 | 04 00 | f4 ff 2d 00 53 00 | a7 df
```

（`f4 ff`=−12 补码 LE，`2d 00`=45，`53 00`=83）

### PLACE（seq=4，颜色 1，微调 fine_x=−15mm，fine_y=30mm）

```
a5 07 00 04 d8 | 05 00 | 01 f1 ff 1e 00 | a3 84
```

### PICK（seq=5，颜色 2，偏移 10mm，−20mm）

```
a5 07 00 05 86 | 06 00 | 02 0a 00 ec ff | 75 43
```

### HEARTBEAT（seq=6，空 data，总长=9）

```
a5 02 00 06 51 | 01 00 | 99 e5
```

### ACK（确认 seq=2 的帧）

```
a5 03 00 01 79 | 07 00 | 02 | e4 39
```

### POSE 上行（seq=0，x=1520mm，y=300mm，heading=−123.4°→−1234，odom=1m）

```
a5 0a 00 00 a9 | 11 00 | f0 05 2c 01 2e fb 01 00 | 96 35
```

（`2e fb`=−1234 补码 LE，`01 00`=1，odom uint16）

### DONE 上行（seq=0，task_id=7）

```
a5 03 00 00 27 | 13 00 | 07 | ad f8
```

### STATE 上行（state=3）

```
a5 03 00 00 27 | 12 00 | 03 | 55 e4
```

（STATE 与 DONE 的帧头 CRC8 同为 `0x27`：帧头只覆盖 SOF/len/seq，二者长度与 seq

```
a5 08 00 07 65 | 03 00 | ff 7f 00 80 b0 b9 | 69 eb
```

## 5. 时序与容错参数（冻结项）

| 参数 | 值 | 来源 |
|---|---|---|
| HEARTBEAT 周期 | 500ms | `timing.heartbeat_ms` |
| 无来流超时 | 2s → SAFESTOP | `timing.heartbeat_timeout_s` |
| ACK 超时 | 100ms 重发 | `timing.ack_timeout_ms` |
| ACK 重试上限 | 3 次失败 → SAFESTOP | `timing.ack_retry` |
| POSE 上报频率 | 10Hz | `MockMcu(pose_hz=10)` 同模型 |

心跳帧不占用 ACK 待确认槽位（发送方不依赖心跳的 ACK）；接收侧对任何帧（含心跳）
均可回 ACK。发送侧**控制帧串行化**：上一条控制帧（TASK_PLAN/GOTO/CALIBRATE/PLACE）
的 ACK 未解决（含重发预算未耗尽）之前不会发出下一条控制帧，预算耗尽仍无 ACK 则记
ACK_TIMEOUT 并 SAFESTOP；NAV/PLACE 超时重发每次重开完整超时窗口（RETRY(n) 语义，
缺省 8s × 2 次重发）。

## 6. 已知限制与实现裁决（必读）

以下为实现代码的真实行为，与规格文字有差异或规格未覆盖，**以代码为准**并共同冻结：

### 6.1 坐标 int16 量程与「饱和不回绕」

x/y 为 int16、单位 mm → 单向表示范围 **−32768 … +32767 mm（约 ±32.7 m）**，远超赛场
尺寸，正常使用不会触界。超界值处理：**饱和钳位（clamp），不是回绕（wrap）**——视觉侧
打包前用 `_i16()`（`max(−32768, min(32767, v))`），MockMcu 同样 `_clamp_i16()` 并在
钳位时计数告警。主控侧解析无需处理回绕歧义。

### 6.2 航向 0.1° 的回绕约定

heading 为 int16、单位 0.1°。有效角度先回绕到有符号区间
**`[-18000, 18000)`（即 [−180.0°, +180.0°)）** 再打包，公式：

```
h01 = ((h01_raw + 18000) % 36000) - 18000     # h01_raw 为 0.1° 单位的任意整数
```

原因：Python `%` 恒非负，负净航向会被映射到 `[1, 35999]`，≥32768 时 `struct '<h'`
直接抛异常——已实现并测试固化。CALIBRATE 的 dhead 同理：视觉侧取先归一到 ±180°
的差值再 ×10。**回绕后仍超 ±32767 的值不存在（回绕区间是 int16 子集），故 heading
不会走饱和路径。**

### 6.3 odom 为 uint16 米

POSE 的里程字段 0..65535 m，超出后按 `& 0xFFFF` 回绕（赛场里程 <100m，无实际影响）。

### 6.4 TASK_PLAN 字节序裁决

规格表曾写作 `batch1[3] batch2[3] pos1 pos2 posS`，**实现按批次分组**：
`b1色(3) | b1位(3) | b2色(3) | b2位(3)` 共 12 字节（与二维码 4 组数字
`452+321+254+312` 的字面顺序一一对应，便于对账）。以本文与 §4 黄金样例为准。

### 6.5 PLACE 第一字节语义

规格写作 `ring_id`，当前 FSM 外发时填**该批次首个物料颜色号**（PLACE1=
`batch1_colors[0]`、PLACE2=`batch2_colors[0]`，1-6，与二维码颜色组首位一致）。
fine_x/fine_y 为视觉微调量字段，**当前恒发 0**（逐件精细放置偏移属 Phase-4）。
放置目标环编号已含在 TASK_PLAN 的位置字节中。若电控组需要 PLACE 携带独立
ring_id，请在联调前提出，改 `_s_PLACE1/2` 一处即可。

### 6.6 PICK / STATE 当前未使用

`PICK(0x0006)` 帧格式已定义、MockMcu 已按「动作命令 → 延迟 1 tick 回 DONE」处理，
但当前 FSM 状态序列中没有取料动作，不会外发；`STATE(0x0012)` 视觉侧收到后仅记录。
两者为联调预留，电控组可按本表实现亦可暂缓。

### 6.7 视觉侧坐标系与校准输入口径（电控组必读）

校准帧 `CALIBRATE` 下发的 `dx,dy,dhead` 是**场地坐标系下的绝对修正量**，来源：
「三色环在图像中的位置 → 经相机安装外参换到车体毫米 → 用**主控最近上报的位姿**
换到场地毫米」，再与场地图理论环心比较。因此：

- 视觉侧观测的坐标系与主控上报位姿**必须同一套**（原点=扫码区角点，mm，右/前为
  +x/+y）。若主控坐标系定义与此不同，校准量会整体错位——联调第一件事就是对齐
  坐标系与单位。
- 校准量依赖 `POSE` 上报的时效性：视觉用最近一帧 POSE 位姿做换算，10Hz 上报下
  延迟 ≤100ms，车静止于三色环前时无影响；若主控在校准窗口内仍在移动，请先停稳
  再让视觉采样。
- 视觉侧在**未完成相机外参标定**时会拒绝进入 live 模式（退出码 2），不会发出未
  校准的修正量。

## 7. 与 v0.1 的差异（迁移清单）

| 项 | v0.1 | v0.2 |
|---|---|---|
| 帧头 | `AA 55` + len(1B) + seq(1B) + cmd(1B) | `A5` + data_length(2B) + seq(1B) + **CRC8(1B)** |
| 命令码 | 1 字节（`0x10`…`0x22`） | **2 字节**（`0x0001`…`0x0013`） |
| 数据段 | `payload` | `data`（语义相同，改名以对齐参考帧结构） |
| 长度字段 | 含头尾总长（1B，上限 255） | `len(data)+2`（2B，**不含头尾**，上限 1026） |
| 校验 | 单字节 XOR + 帧尾 `0D` | **CRC8 帧头 + CRC16 整包** |
| 固定开销 | 7 字节 | 9 字节 |
