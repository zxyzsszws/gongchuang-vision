应答与重发规则（V2.1.0 定稿）

只有两处往返需要应答，都不是额外的 ack 帧：

  1. 0x0006 的应答就是 0x0008。电控发出臂状态后等解算帧； 超时没等到，就认为视觉没收到，重发臂状态（seq 不变）。 视觉收到同一个 seq 时，原样重发上一帧 0x0008，不重新解算。
  2. done 就是 0x0007 带结果字节。视觉发出 0x0008 后等 done； 超时没等到，就认为电控没收到，重发解算帧（seq 不变）。 电控按 echo_seq 认出这帧执行过了，只补一次 done。
  3. 超时取值不同。纯收帧的应答超时是 100ms；等 done 是 2000ms， 因为 done 在动作执行完才发，用 100ms 判会一直误判、疯狂重发。
  4. 重发有上限。两边各自最多重发 3 次；第 3 次仍失败就安全停止， 不继续动作，也不假装成功。
  5. 电控按 echo_seq 去重是硬性要求。视觉重发的解算帧 seq 不变， 电控若会计数，车会沿同一个 shift_x 走两遍——这类错误不报错， 只表现为位置错。

本版本没有心跳。周期测量帧（位姿、转盘，各 20Hz）本身就是链路活跃的证据； 而电控是事件驱动的，停着作业时可能十几秒不发一帧，把静默当断链只能得到误报。 链路死掉一定会在上面两处往返之一暴露出来。

左侧「丢包场景」可以分别验证：解算帧丢、done 丢、两者都丢、done 一直丢。 打叉的连线就是丢掉的帧，同一方向上后面那条就是重发。

本版本确定的约定

  1. 坐标系：电机坐标系原点在车身右侧边的中点（臂的转轴）， +x 沿车头方向，+y 指向车身外侧，车身本体落在 y < 0 一侧。
    这条已写进协议附录二第三节。
  2. l 是水平伸出长度，比赛中固定死，不作为一个可调自由度； h 是相机离地高度，用于把像素折算成毫米。
  3. α 从 +x 量起、向 +y 为正，是绝对角，不是相对当前 yaw 的增量。
    所以 0x0008 直接给出最终该转到的角度，电控自己算差值。
  4. d 是相对当前车身位置的位移，正为前进、负为后退，单位 mm。
    视觉每轮从零算，不做跨帧累积；电控执行完不必回报「我现在在哪」。
  5. 执行顺序：先挪车 shift_x，再转臂 arm_yaw。 反过来臂会先摆到目标方向，挪车时扫过更大范围。
  6. 电控在等解算时必须静止。从发出 0x0006 到收到 done 之前，底盘不动、 臂不转、升降不调——否则解出的 d 对应一个已经不存在的姿态。
  7. 够不着就报够不着。|y| > l 时状态字节 bit0~1 = 1，不钳位： 钳位会给出一个「看起来能到、实际差一截」的答案，电控抓空却不报错。
  8. 命令码：0x0006 臂状态（电控→视觉，7B）、0x0008 解算结果 （视觉→电控，10B）、done 复用 0x0007（2B：ack_seq + 结果字节）。
