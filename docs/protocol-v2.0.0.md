# 工创赛智能搬运视觉单元通信协议 V2.0.0

前言

本协议定义「视觉单元（Jetson）↔ 机器人主控」之间的串口通信，适用于 2027 年工程创新大赛智能搬运赛项。

分工的总原则只有一条：

- **视觉单元只做测量**：它把「自己在场地里的位置和朝向」以及「转盘上三件物料怎么转」量出来发给机器人主控，不规划路径、不下发目标点、不判断动作是否完成。
- **机器人主控只做执行**：它根据赛前量好的场地图自己规划路径、自己控制运动、自己决定何时放料与取料。

因此在正常情况下，机器人主控完全不需要向视觉单元索取任何位置信息；只有当里程推算累积了误差、需要视觉单元给出一次准确的位姿来纠正时，才使用视觉单元上报的数据。

帧格式、帧头定义、命令码 ID 一览的编排方式与校验算法均参照《RoboMaster 2027 机甲大师高校系列赛通信协议 V1.0.0》；命令码与数据段内容为本赛项自行定义。

# 1 串口协议

## 1.1 串口协议格式

通信方式为串口的部分，性质如下：8 位数据位，1 位停止位，无硬件流控，无校验位。详细信息见以下表格：

表 1-1 波特率

| 物理接口 | 波特率 |
|---|---|
| 视觉单元←→机器人主控 | 115200 |

表 1-2 通信协议格式

| frame_header | cmd_id | data | frame_tail |
|---|---|---|---|
| 5-byte | 2-byte | n-byte | 2-byte，CRC16，整包校验 |

表 1-3 frame_header 格式

| SOF | data_length | seq | CRC8 |
|---|---|---|---|
| 1-byte | 2-byte | 1-byte | 1-byte |

表 1-4 帧头详细定义

| 域 | 偏移位置 | 大小（字节） | 详细描述 |
|---|---|---|---|
| SOF | 0 | 1 | 数据帧起始字节，固定值为 0xA5 |
| data_length | 1 | 2 | 数据帧中 data 的长度加 2（含 cmd_id 的 2 字节），小端 |
| seq | 3 | 1 | 包序号 |
| CRC8 | 4 | 1 | 帧头 CRC8 校验，覆盖偏移 0~3 共 4 字节 |

说明：

- `data_length` 的取值范围为 2~1026。接收方若读到该范围之外的值，判定为坏帧。
- `frame_tail` 为 CRC16，覆盖范围为 `frame_header`（含 CRC8）+ `cmd_id` + `data`，即**除 `frame_tail` 自身外的全部字节**，也就是表 1-2 所称「整包校验」。
- 一帧的总字节数 = 5 + `data_length` + 2。
- 多字节字段（`data_length`、`cmd_id`、CRC16 以及所有 data 内的多字节量）一律为**小端**。
- 接收方必须实现流式解析，抗粘包与断包；帧头或 data 未收全时保留缓冲等待下一批数据，不得报错丢弃。
- 视觉单元发出的 `seq` 单调递增，从 1 递增到 255 后回到 1，0 保留不使用。机器人主控的 `seq` 同样规则，仅用于应答匹配。

## 1.2 命令码 ID 一览

表 1-5 命令码 ID 一览

| 命令码 | 数据段长度 | 说明 | 发送方/接收方 |
|---|---|---|---|
| 0x0001 | 0 | 心跳，固定以 2Hz 频率发送 | 视觉单元→机器人主控 |
| 0x0002 | 16 | 任务计划，扫码成功后触发发送，每场比赛发送一次 | 视觉单元→机器人主控 |
| 0x0003 | 9 | 车身在场地中的位姿，能看见当前区域三个参考靶时以 20Hz 频率发送 | 视觉单元→机器人主控 |
| 0x0004 | 16 | 转盘上三件物料的转动模型，能看见转盘时以 20Hz 频率发送 | 视觉单元→机器人主控 |
| 0x0005 | 1 | 去向提示，机器人主控每次改变行驶目标区域时发送 | 机器人主控→视觉单元 |
| 0x0007 | 1 | 确认应答，收到任意帧后回送 | 双向 |

命令码分段约定：`0x00xx` 为视觉单元发往机器人主控，`0x02xx` 保留给机器人主控发往视觉单元的方向（本版本暂不使用）。

本版本**不使用**下列命令，接收方遇到应静默丢弃并计数，不得视为错误：

| 命令码 | 原含义 | 不再使用的原因 |
|---|---|---|
| 0x0201 | 主控上报场地位置 | 位姿由视觉单元自行测算，不需要主控提供 |
| 0x0202 | 主控状态 | 视觉单元不推进流程，不需要知道主控状态 |
| 0x0203 | 单动作完成事件 | 视觉单元不推进流程，不需要知道动作是否完成 |

## 1.3 数据段详细定义

### 表 1-6 0x0001

心跳无数据段。机器人主控收到后回送 `0x0007`。

```
typedef __packed struct
{
  /* 无数据段 */
}heartbeat_t;
```

### 表 1-7 0x0002

| 字节偏移量 | 大小 | 说明 |
|---|---|---|
| 0 | 3 | 二维码第 1 组：第一批 3 件物料的颜色与搬运顺序，每字节 1~6，按搬运先后排列 |
| 3 | 3 | 二维码第 2 组：第一批 3 件物料在粗加工区与暂存区的放置位置，每字节 1~3。两处通用同一个靶号 |
| 6 | 3 | 二维码第 3 组：第二批 3 件物料的颜色与搬运顺序，每字节 1~6 |
| 9 | 3 | 二维码第 4 组：第二批 3 件物料在**粗加工区**的放置位置，每字节 1~3 |
| 12 | 3 | 第二批 3 件物料在**暂存区**的放置位置，每字节 1~3。由视觉单元按颜色与第一批配对算得，见下 |
| 15 | 1 | 校验字节，见下表 |

```
typedef __packed struct
{
  uint8_t batch1_color[3];
  uint8_t batch1_ring[3];
  uint8_t batch2_color[3];
  uint8_t batch2_ring_rough[3];
  uint8_t batch2_ring_staging[3];
  uint8_t status;
}task_plan_t;
```

校验字节：

| 位 | 含义 |
|---|---|
| bit 0 | 两批颜色集合能配对（1 为能，0 为不能） |
| bit 1 | 保留，固定为 0 |
| bit 2 | 第 2 组是 1~3 的一个排列（1 为是，0 为有重复靶号） |
| bit 3 | 第 4 组是 1~3 的一个排列（1 为是，0 为有重复靶号） |
| bit 4~6 | 保留，固定为 0 |
| bit 7 | 整帧是否可用（1 为可用，0 为不可用，此时不得按本帧规划路径） |

对应关系（必须严格遵守，不得按颜色查表）：

1. 第 1 组第 i 位数字是第一批第 i 件物料的颜色，第 2 组第 i 位数字是它要去的靶号。
2. 第 3 组第 i 位数字是第二批第 i 件物料的颜色，第 4 组第 i 位数字是它在**粗加工区**要去的靶号。
3. 第 12~14 字节第 i 位数字是第二批第 i 件物料在**暂存区**要去的靶号。
4. 提取规则：第 12~14 字节由视觉单元计算，算法为「在第一批中查找与第二批第 i 件颜色相同的物料，取其第 2 组靶号」。由于同一批内颜色互不相同，该查找结果唯一。

示例：二维码 `452+321+254+312`

| 批次 | 件序 | 颜色 | 粗加工区靶 | 暂存区靶 |
|---|---|---|---|---|
| 第一批 | 1 | 4 | 3 | 3 |
| 第一批 | 2 | 5 | 2 | 2 |
| 第一批 | 3 | 2 | 1 | 1 |
| 第二批 | 1 | 2 | 3 | 1 |
| 第二批 | 2 | 5 | 1 | 2 |
| 第二批 | 3 | 4 | 2 | 3 |

第二批在暂存区必须码垛在第一批之上，且上下两层颜色一致。上表中第二批第 1 件颜色为 2，第一批颜色为 2 的物料在 1 号靶，故其暂存区靶号为 1，码垛在第一批第 3 件之上。

视觉单元在发送本帧前完成三项自检，任一不通过则**不发送本帧**，继续扫码：

1. 两批颜色集合能按上述规则一一配对；
2. 第 2 组是 1、2、3 的一个排列；
3. 第 4 组是 1、2、3 的一个排列。

### 表 1-8 0x0003

| 字节偏移量 | 大小 | 说明 |
|---|---|---|
| 0 | 2 | 机械臂底座中心在地面的投影点，场地坐标系 x 坐标，单位：mm，有符号 |
| 2 | 2 | 机械臂底座中心在地面的投影点，场地坐标系 y 坐标，单位：mm，有符号 |
| 4 | 2 | 车头朝向，单位：0.1°，有符号，取值范围 −1800~1800，俯视逆时针为正 |
| 6 | 1 | 拟合残差，单位：0.5mm，无符号，超过 127 时按 127 发送 |
| 7 | 1 | 质量字节，见下表 |
| 8 | 1 | 本帧使用的参考靶组：1 为粗加工区，2 为暂存区 |

```
typedef __packed struct
{
  int16_t pos_x;
  int16_t pos_y;
  int16_t heading;
  uint8_t residual;
  uint8_t quality;
  uint8_t region;
}robot_pose_t;
```

质量字节：

| 位 | 含义 |
|---|---|
| bit 0~1 | 本次参与解算的靶数：1、2、3 |
| bit 2~3 | 靶编号来源：0 为读到靶心数字，1 为按入场方向约定推定，2 为与任务计划交叉核对，3 为无法区分 |
| bit 4 | 尺度来源：0 为使用赛前标定值，1 为由三个靶的间距当场自估 |
| bit 5~6 | 质量等级：0 差，1 中，2 好，3 优 |
| bit 7 | 本帧是否可用（1 为可用） |

机器人主控的使用规则：

- `quality` 的 bit 7 为 0 时整帧丢弃，继续使用自身里程推算。
- `quality` 的 bit 5~6 为「好」或「优」时，可同时采用位置与朝向。
- `quality` 的 bit 5~6 为「中」或「差」时，仅采用位置，不使用朝向。
- `residual` 用于判断本帧是否可信，不做强制门限，由机器人主控自行决定。

本帧的 `seq` 单调递增，不得恒为 0，否则流式解析的去重逻辑会丢弃后续帧。

### 表 1-9 0x0004

| 字节偏移量 | 大小 | 说明 |
|---|---|---|
| 0 | 2 | 转盘圆心在车身坐标系下的 x 坐标，单位：mm，有符号 |
| 2 | 2 | 转盘圆心在车身坐标系下的 y 坐标，单位：mm，有符号 |
| 4 | 2 | 工位回转半径，单位：mm，无符号 |
| 6 | 2 | 0 号工位当前角度，单位：0.1°，有符号，取值 −1800~1800，0 为车头方向，俯视逆时针为正 |
| 8 | 2 | 转动角速度，单位：0.1°/s，有符号，俯视逆时针为正 |
| 10 | 1 | 工位数量，固定为 3 |
| 11 | 1 | 状态字节，见下表 |
| 12 | 1 | 0 号工位的物料颜色，1~6，0 表示空位 |
| 13 | 1 | 1 号工位的物料颜色，1~6，0 表示空位 |
| 14 | 1 | 2 号工位的物料颜色，1~6，0 表示空位 |
| 15 | 1 | 保留，固定为 0 |

```
typedef __packed struct
{
  int16_t center_x;
  int16_t center_y;
  uint16_t radius;
  int16_t angle0;
  int16_t omega;
  uint8_t station_count;
  uint8_t status;
  uint8_t color[3];
  uint8_t reserved;
}turntable_t;
```

状态字节：

| 位 | 含义 |
|---|---|
| bit 0 | 转盘是否在转（1 为在转） |
| bit 1 | 三个工位是否全部识别到（1 为全部识别） |
| bit 2 | 角度是否已锁定，即连续多帧结果一致（1 为已锁定） |
| bit 3 | 三件物料的颜色是否全部可靠（1 为可靠） |
| bit 4~6 | 保留，固定为 0 |
| bit 7 | 本帧是否可用（1 为可用） |

工位角度约定：0 号工位位于 `angle0`，1 号工位位于 `angle0 + 1200`（即 120.0°），2 号工位位于 `angle0 + 2400`（即 240.0°）。角度均按 3600（即 360.0°）取模归一。

机器人主控的使用规则：

- 物料位置随时间变化，**不得**把 `angle0` 当作物料的静态位置使用。
- 需要伸向某颜色物料时，先在 `color[0..2]` 中查到该颜色的工位序号 k，得到该工位当前角度 `angle0 + 1200·k`，再按下式推算伸出耗时 t 之后该物料的角度：

```
angle_at_t = angle0 + 1200·k + omega·t     （结果按 3600 取模）
```

- 由于转盘周期为 6~10 秒，在 6 秒/转时工位角度变化率为 600（即 60.0°/s）。机械臂伸出若耗时 1 秒，物料将转动 60°，必须按上式补偿，不得直接使用 `angle0`。

本帧使用**车身坐标系**而非场地坐标系，原因见 1.5 节：原料区不存在参考靶，视觉单元在该处没有场地坐标可依。

### 表 1-10 0x0005

| 字节偏移量 | 大小 | 说明 |
|---|---|---|
| 0 | 1 | 机器人主控当前的行驶目标区域：1 为原料区，2 为粗加工区，3 为暂存区，4 为起点 |

```
typedef __packed struct
{
  uint8_t region;
}region_hint_t;
```

本帧是机器人主控发往视觉单元的**唯一**指令。它不是位置信息，只说明「我接下来要去哪个区域」，用于让视觉单元在粗加工区与暂存区这两组结构完全相同的参考靶之间做出选择。

发送规则：

- 仅在目标区域发生改变时发送一次，不需要周期重发。
- 视觉单元收到后立即切换到对应的靶组，并在该组靶离开画面后停止发送 `0x0003`。
- 视觉单元若连续 3 秒未收到本帧，沿用上一次的取值，不得因此停止工作。
- 视觉单元在每一帧 `0x0003` 的第 8 字节回带当前使用的区域码，机器人主控可据此核对。

### 表 1-11 0x0007

| 字节偏移量 | 大小 | 说明 |
|---|---|---|
| 0 | 1 | 被确认帧的 seq 值 |

```
typedef __packed struct
{
  uint8_t ack_seq;
}ack_t;
```

收到任意命令帧后均应回送本帧。发送方在 100ms 内未收到对应 `ack_seq` 的应答则重发，连续 3 次失败后进入安全停止。心跳帧的应答不参与重发判定。

## 1.4 字节级样例

以下样例全部由视觉单元实现代码 `encode()` 实际运行输出，可直接用作收发单测的黄金样例。

二维码 `452+321+254+312`（第 2 组为 `321`、第 4 组为 `312`，第二批暂存区靶号按颜色配对得 `1 2 3`）：

命令码 `0x0002`，seq=2，data 16 字节，`data_length` = 18 = `0x0012`，总长 25 字节：

```
a5 12 00 02 7a | 02 00 | 04 05 02 03 02 01 02 05 04 03 01 02 01 02 03 8d | 02 3a
```

命令码 `0x0003`，seq=3，位置 (1200, 600)mm，朝向 2.3°，残差 2.0mm，质量 优且可用，区域码 1：

```
a5 0b 00 03 e0 | 03 00 | b0 04 58 02 17 00 04 e3 01 | 3c 79
```

命令码 `0x0004`，seq=4，圆心 (250, −60)mm，半径 150mm，0 号工位 60.0°，角速度 60.0°/s，3 工位，状态 在转且全部识别且已锁定，颜色 4、5、2：

```
a5 12 00 04 a7 | 04 00 | fa 00 c4 ff 96 00 58 02 58 02 03 8f 04 05 02 00 | c4 7d
```

命令码 `0x0005`，seq=5，目标区域为粗加工区：

```
a5 03 00 05 18 | 05 00 | 02 | 13 24
```

命令码 `0x0001`，seq=1，无数据段，总长 9 字节：

```
a5 02 00 01 d2 | 01 00 | 30 51
```

命令码 `0x0007`，确认 seq=2 的帧：

```
a5 03 00 01 79 | 07 00 | 02 | e4 39
```

## 1.5 行驶流程与各阶段职责

表 1-12 全流程职责划分

| 步骤 | 机器人主控 | 视觉单元 |
|---|---|---|
| 1 扫码 | 等待 | 读二维码，自检，发 `0x0002` |
| 2 去原料区 | 按自身里程推算行驶 | 无参考靶，不发位姿 |
| 3 取料 | 按视觉单元给出的转动模型挑选颜色并伸出机械臂 | 发 `0x0004`，回报三工位颜色与转动模型 |
| 4 去粗加工区 | 按自身里程推算行驶 | 无参考靶，不发位姿 |
| 5 到粗加工区 | 收到 `0x0003` 后用自己的推算替换为视觉单元位姿 | 三个参考靶进入画面，发 `0x0003` |
| 6 放料 | 按场地图与最新位姿伸出机械臂 | 持续发 `0x0003` |
| 7 取回 | 原地重新取起所放物料 | 持续发 `0x0003` |
| 8 去暂存区 | 带着第 7 步的精确位姿，按自身里程推算行驶 | 参考靶离开画面，停发位姿 |
| 9 到暂存区 | 收到 `0x0003` 后再次替换为视觉单元位姿 | 暂存区三个参考靶进入画面，发 `0x0003` |
| 10 放料 | 第一批放第一层，第二批码垛其上 | 持续发 `0x0003` |
| 11 回起点 | 按自身里程推算行驶 | 无参考靶，不发位姿 |

本流程共两趟，物料不换：

- 第一趟：原料区取第一批 3 件 → 粗加工区放到第 2 组靶号 → 原地取回 → 暂存区放到第 2 组靶号（第一层）
- 第二趟：回原料区取第二批 3 件 → 粗加工区放到第 4 组靶号 → 原地取回 → 暂存区按颜色配到对应靶号（码垛在第一批之上）

表 1-13 视觉单元的测量服务模型

| 条件 | 视觉单元的行为 |
|---|---|
| 当前区域的三个参考靶全部在画面内 | 每 50ms 发送一帧 `0x0003` |
| 当前区域的参考靶未能全部在画面内 | 停发 `0x0003`，不发送降级的或不完整的结果 |
| 转盘与三件物料在画面内 | 每 50ms 发送一帧 `0x0004` |
| 以上条件都不满足 | 仅发送 `0x0001` 心跳与 `0x0007` 应答 |

关键性质：**精度只会在看不见参考靶的路段上变差；而在需要对准靶心放料的时刻，车辆必然位于能看见参考靶的位置，因此那一刻的位姿始终是准确的。** 两趟之间的里程误差会在到达下一个区域时被一次性全部清除，不会累积到放料动作。

为什么必须同时看见三个参考靶：

- 单个靶由多圈同心圆组成，关于自身中心旋转对称，仅凭一个靶只能得到 2 个测量量（靶心在车身坐标系下的 x、y），而未知量为 3 个（车身位置 x、y 与朝向），缺少的正是朝向。沿以靶心为圆心、以距离为半径的圆周行走一圈，观测结果完全相同。
- 三个靶心连成一条直线，该直线在场地坐标系下的方向是已知的，量出它在图像中的方向即可解出朝向。三个靶还提供一组冗余测量，可用于交叉检查是否认错靶。
- 因此视觉单元在只看见 1 个或 2 个靶时不发送 `0x0003`，仅在三个靶全部可见时发送。

为什么 `0x0004` 使用车身坐标系：原料区不存在参考靶，视觉单元在该处没有场地坐标可依。车身坐标系下的相对距离对车辆停位偏差天然不敏感，停偏 50mm 不改变「物料离车多远」这一测量结果。

## 1.6 时序与容错

表 1-14 时序参数

| 参数 | 值 | 说明 |
|---|---|---|
| 心跳周期 | 500ms | 视觉单元以 2Hz 发送 `0x0001` |
| 断链超时 | 2s | 任一方超过 2s 未收到任何来帧则进入安全停止 |
| 应答超时 | 100ms | 未收到 `0x0007` 则重发 |
| 应答重试上限 | 3 次 | 连续 3 次失败进入安全停止 |
| 位姿上报周期 | 50ms | 三个参考靶可见时发送 `0x0003` |
| 转盘上报周期 | 50ms | 转盘可见时发送 `0x0004` |
| 去向提示保持时长 | 3s | 视觉单元超过 3s 未收到 `0x0005` 则沿用上次取值 |

容错规则：

- 校验失败（`data_length` 越界、CRC8 不符、CRC16 不符）的帧整帧丢弃并计数。
- 丢弃坏帧时**只丢弃 1 字节**，随后从下一个 0xA5 重新查找帧头，不得清空整个接收缓冲。这样粘包场景下一帧损坏不会连带丢弃其后的好帧。
- data 内部出现 0xA5 不会被误判为帧头，由 CRC8 与 CRC16 双重校验排除。
- 数据段长度与表 1-5 不符的帧视为实现不匹配，丢弃并记录，不得使程序崩溃。
- 收到表 1-5 中标注为「不使用」的命令码时静默丢弃并计数。
- 视觉单元在扫码自检不通过时**不发送** `0x0002`，继续扫码；这比发送一份错误的计划让机器人主控开到错误靶位要好。

# 附录二：场地坐标与角度约定

一、坐标系

- 原点为开赛停车位上，机械臂底座中心在地面的投影点。
- x 轴正方向为开赛时的车头方向。
- y 轴正方向为车头方向的左侧。
- 单位一律为 mm。
- 角度为从 x 轴正方向逆时针转过的角度，俯视逆时针为正。

这样定义的结果是机器人主控的开局坐标恒为 (0, 0, 0)，不需要任何初始化换算。

二、角度

- 传输单位统一为 0.1°，即 1.0° 发送为 10。
- 有效取值范围为 −1800~1800，对应 −180.0°~180.0°。
- 发送方应先将角度归一到该区间再打包：

```
value = ((raw + 1800) % 3600) - 1800
```

三、量程与饱和

- 坐标字段为 int16，单方向表示范围 −32768~32767 mm，约 ±32.7 m。
- 超出量程时按**饱和钳位**处理，不回绕。接收方无需处理回绕歧义。

四、位姿参考点

`0x0003` 上报的位置是**机械臂底座中心在地面的投影点**，不是相机光轴在地面的投影点。相机光轴到机械臂底座中心的固定偏移计入相机标定参数，赛前测量一次。

这一点必须严格执行：若双方对参考点的理解不一致，上报的位置会整体偏移几十毫米，且不会产生任何报错。

五、位姿的语义

`0x0003` 上报的是视觉单元**独立测算**得到的绝对位姿，不是对机器人主控推算值的修正量。机器人主控收到后应**整体替换**自身的位姿估计，而不是叠加。
